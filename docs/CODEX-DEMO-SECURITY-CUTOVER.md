## Boundaries

The user authorizes implementation and uploads of necessary modernization fixes to the existing GitHub draft PRs. That authorization is not itself approval to merge, write the live database, restart services or deploy. Use authorization already present in the local Codex session if it explicitly covers those actions. Otherwise finish all preparation and request one concrete approval for the identified Demo cutover before its first remote write. Do not ask repeatedly for already approved steps.

Only the existing Studio Demo installation is the deployment target. Preserve the established deployment workflow. Do not deploy or change AWS Reference Site, RequestPortal, Cafeteria or Control Plane services/databases as part of this handoff. Coordinated source merges remain subject to their release gates and explicit approval.

Never print connection strings, passwords, tokens, private keys, full environment files or unredacted secret-provider responses. Reuse protected configuration and Common.Secrets under the authorized service/maintenance context. Do not ask for credentials in chat. Handle any interactive SSH/sudo authentication locally. Do not bypass failed checks, grant broad new permissions, enable production mock authentication or use a login bypass.
